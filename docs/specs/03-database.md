# Tutor Link — Database Design

Nov 16, 2026 · @Zakari DARO

## 1. Overview

Phase 1 uses 71 tables in one PostgreSQL 16 database with the PostGIS, `citext`, `pgcrypto` and `btree_gist` extensions. The SQL below is the reference schema; Prisma models are generated to match it.

**Conventions**

| Topic | Rule |
| --- | --- |
| Names | Singular `snake_case` tables and columns |
| Standard columns | Every table has `id uuid primary key`, `created_at timestamptz`, `updated_at timestamptz`. They are not repeated in the SQL below |
| IDs | UUID v7 generated by the API, so rows sort by creation time |
| Time | `timestamptz` in UTC. Display in Africa/Accra |
| Money | `bigint` in pesewas with a `_pesewas` suffix. Rates in basis points with a `_bps` suffix |
| Enums | PostgreSQL enum types, listed with their first use |
| Encrypted fields | `bytea` with an `_enc` suffix, encrypted by the API with a managed key |
| Soft delete | `deleted_at timestamptz` on tables holding personal data |
| Tenancy | `organisation_id` on tenant-owned tables, defaulting to the platform organisation |
| Foreign keys | Always indexed. `on delete restrict` unless stated |

**Three names changed from the architecture document**

- `user` is a reserved word in PostgreSQL, so the table is `user_account`.
- The login session is `auth_session` and a tutoring lesson is `lesson_session`, to stop the two being confused.
- `booking_package` is dropped. A `booking` holds one or many `lesson_session` rows, which covers single lessons and packages with one model.

## 2. Relationship map

&#91;embedded content: core tables · 20 of 57, simplified\]

The booking is the hub: it joins a guardian's child to a tutor, owns the lesson sessions, and is paid for by a payment. Each session carries its check-ins, report, review and any incident, and is paid out to the tutor exactly once. Lookup, audit and messaging tables are left out to keep the map readable.

## 3. Identity and family

Eleven tables hold accounts, roles, logins, guardians and children. Owner: Identity and Access module, except the family tables, which it shares through a service.

```sql
create type user_status as enum ('active','suspended','deactivated');
create type role_type   as enum ('guardian','tutor','student','org_member','staff');
create type staff_role  as enum ('super_admin','operations','safeguarding','finance',
                                 'support','moderator','marketing');
create type otp_purpose as enum ('login','signup','step_up','session_checkin');
create type consent_type as enum ('terms','privacy','guardian_for_child',
                                  'kyc_check','record_sharing','marketing');

create table user_account (
  phone_e164        text not null unique,
  email             citext unique,
  full_name         text not null,
  status            user_status not null default 'active',
  phone_verified_at timestamptz,
  phone_changed_at  timestamptz,          -- drives the payout cooling-off period
  last_login_at     timestamptz,
  deleted_at        timestamptz
);

create table user_role (
  user_id         uuid not null references user_account,
  role            role_type not null,
  organisation_id uuid not null references organisation,
  unique (user_id, role, organisation_id)
);

create table auth_session (
  user_id            uuid not null references user_account,
  family_id          uuid not null,       -- all rotations of one login
  refresh_token_hash text not null unique,
  user_agent         text,
  ip                 inet,
  expires_at         timestamptz not null,
  revoked_at         timestamptz
);

create table otp_challenge (
  phone_e164  text not null,
  purpose     otp_purpose not null,
  code_hash   text not null,
  attempts    smallint not null default 0 check (attempts <= 5),
  expires_at  timestamptz not null,

);

create table staff_profile (
  user_id         uuid not null unique references user_account,
  staff_role      staff_role not null,
  totp_secret_enc bytea,
  mfa_enrolled_at timestamptz
);

create table staff_permission (
  staff_role staff_role not null,
  permission text not null,               -- e.g. 'payout.approve'
  unique (staff_role, permission)
);

create table guardian_profile (
  user_id     uuid not null unique references user_account,
  locality_id uuid references locality
);

create table guardian_address (
  guardian_id       uuid not null references guardian_profile,
  label             text not null default 'Home',
  address_enc       bytea not null,
  ghanapost_gps_enc bytea,
  location          geography(Point,4326),  -- used for distance only
  locality_id       uuid not null references locality,
  deleted_at        timestamptz
);

create table child_profile (
  guardian_id    uuid not null references guardian_profile,
  first_name     text not null,
  class_level_id uuid not null references class_level,
  learning_goals text,
  deleted_at     timestamptz
);

create table child_subject (
  child_id   uuid not null references child_profile on delete cascade,
  subject_id uuid not null references subject,
  unique (child_id, subject_id)
);

create table consent_record (
  user_id        uuid not null references user_account,
  child_id       uuid references child_profile,
  consent        consent_type not null,
  policy_version text not null,
  granted_at     timestamptz not null,
  withdrawn_at   timestamptz,
  ip             inet
);
```

`child_profile` holds no surname, photo, school name, date of birth or national ID. `guardian_address` is readable only by the Booking service, and only for a paid booking.

## 4. Tutor and verification

Eight tables describe what a tutor offers and how far they are verified. Owners: Tutor Profiles and Verification modules.

```sql
create type listing_status   as enum ('draft','in_review','listed','hidden','suspended');
create type lesson_mode      as enum ('home','online');
create type kyc_status       as enum ('pending','passed','failed','expired','abandoned');
create type credential_type  as enum ('degree','diploma','teaching_certificate',
                                      'ntc_licence','reference','other');
create type review_decision  as enum ('pending','approved','rejected','more_info');
create type verification_action as enum ('granted','revoked','expired','renewed');

create table tutor_profile (
  user_id              uuid not null unique references user_account,
  organisation_id      uuid not null references organisation,
  headline             text,
  bio                  text,
  years_experience     smallint check (years_experience between 0 and 60),
  hourly_rate_pesewas  bigint check (hourly_rate_pesewas > 0),
  teaches_home         boolean not null default false,
  teaches_online       boolean not null default false,
  base_location        geography(Point,4326),
  travel_radius_km     smallint check (travel_radius_km between 1 and 100),
  locality_id          uuid references locality,
  listing_status       listing_status not null default 'draft',
  verification_level   smallint not null default 0 check (verification_level between 0 and 5),

create table tutor_subject (

  rate_pesewas   bigint check (rate_pesewas > 0),   -- overrides the hourly rate
  unique (tutor_id, subject_id, class_level_id, curriculum_id)
);

create table availability_slot (
  tutor_id   uuid not null references tutor_profile on delete cascade,
  weekday    smallint not null check (weekday between 0 and 6),
  start_time time not null,
  end_time   time not null check (end_time > start_time),
  mode       lesson_mode not null
);

create table availability_exception (
  tutor_id     uuid not null references tutor_profile on delete cascade,
  on_date      date not null,
  is_available boolean not null default false,
  note         text
);

create table kyc_check (
  tutor_id           uuid not null references tutor_profile,
  provider           text not null,
  provider_reference text not null,
  status             kyc_status not null default 'pending',
  masked_id_number   text,                 -- e.g. 'GHA-*******-4'
  attempt_no         smallint not null default 1,
  consent_record_id  uuid not null references consent_record,
  completed_at       timestamptz,
  unique (provider, provider_reference)
);

create table credential (
  tutor_id       uuid not null references tutor_profile,
  type           credential_type not null,
  title          text not null,
  issuer         text,
  licence_number text,                     -- NTC licence number
  file_key       text,                     -- private object storage key
  status         review_decision not null default 'pending',
  expires_at     date,
  deleted_at     timestamptz
);

create table credential_review (
  credential_id      uuid not null references credential,
  reviewer_id        uuid not null references user_account,
  second_reviewer_id uuid references user_account,
  decision           review_decision not null,
  reason             text not null,
  check (second_reviewer_id is null or second_reviewer_id <> reviewer_id)
);

create table verification_event (
  tutor_id    uuid not null references tutor_profile,
  level       smallint not null check (level between 1 and 5),
  action      verification_action not null,
  actor_id    uuid references user_account,   -- null when automatic
  reason      text,
  valid_until date
);
```

`kyc_check` has no column for a card image, a full card number, a selfie or any biometric value. `credential.file_key` must never point to a Ghana Card; the upload form excludes that document type and reviewers reject it. Levels: 1 Account, 2 Identity, 3 Qualification, 4 Safeguarding, 5 Platform Trusted.

## 5. Marketplace and sessions

Seven tables take a family from a request to a completed, safe lesson. Owners: Discovery and Matching, Booking, and Sessions and Safety modules.

```sql
create type request_status     as enum ('open','matched','closed','expired');
create type application_status as enum ('submitted','shortlisted','accepted','declined','withdrawn');
create type booking_status     as enum ('pending_payment','confirmed','in_progress','completed',
                                        'cancelled','expired','disputed');
create type session_status     as enum ('scheduled','checked_in','completed','missed',
                                        'cancelled','disputed');
create type check_type         as enum ('check_in','check_out');
create type check_method       as enum ('otp','qr','staff_override');
create type incident_category  as enum ('safeguarding','no_show','conduct','payment','quality','other');
create type incident_severity  as enum ('low','medium','high','critical');
create type incident_status    as enum ('open','investigating','resolved','dismissed');

create table tutoring_request (
  guardian_id    uuid not null references guardian_profile,
  child_id       uuid not null references child_profile,
  subject_id     uuid not null references subject,
  class_level_id uuid not null references class_level,
  mode           lesson_mode not null,
  budget_pesewas bigint check (budget_pesewas > 0),
  schedule_notes text,
  locality_id    uuid references locality,
  status         request_status not null default 'open',
  expires_at     timestamptz not null
);

create table request_application (
  request_id            uuid not null references tutoring_request,
  tutor_id              uuid not null references tutor_profile,
  message               text,
  proposed_rate_pesewas bigint not null check (proposed_rate_pesewas > 0),
  status                application_status not null default 'submitted',
  unique (request_id, tutor_id)
);

create table booking (
  reference       text not null unique,          -- human-readable, e.g. TL-7K4M2Q
  organisation_id uuid not null references organisation,
  guardian_id     uuid not null references guardian_profile,
  child_id        uuid not null references child_profile,
  tutor_id        uuid not null references tutor_profile,
  subject_id      uuid not null references subject,
  request_id      uuid references tutoring_request,
  address_id      uuid references guardian_address,   -- required when mode = 'home'
  mode            lesson_mode not null,
  lessons_count   smallint not null check (lessons_count between 1 and 60),
  rate_pesewas    bigint not null check (rate_pesewas > 0),
  total_pesewas   bigint not null check (total_pesewas > 0),
  commission_bps  integer not null check (commission_bps between 0 and 5000),
  status          booking_status not null default 'pending_payment',
  hold_expires_at timestamptz,
  adult_present_ack boolean not null default false,
  cancelled_at    timestamptz,
  cancel_reason   text,
  check (mode <> 'home' or address_id is not null)
);

create table lesson_session (
  booking_id        uuid not null references booking,
  tutor_id          uuid not null references tutor_profile,
  scheduled_start   timestamptz not null,
  scheduled_end     timestamptz not null check (scheduled_end > scheduled_start),
  status            session_status not null default 'scheduled',
  checkin_code_hash text,
  checked_in_at     timestamptz,
  checked_out_at    timestamptz,
  meeting_url       text,                        -- online lessons
  dispute_window_ends_at timestamptz,
  -- no tutor can hold two live sessions that overlap
  exclude using gist (
    tutor_id with =,
    tstzrange(scheduled_start, scheduled_end) with &&
  ) where (status not in ('cancelled','missed'))
);

create table check_event (
  session_id  uuid not null references lesson_session,
  type        check_type not null,
  method      check_method not null,
  actor_id    uuid not null references user_account,
  reason      text,                              -- required for staff_override
  occurred_at timestamptz not null,
  unique (session_id, type),
  check (method <> 'staff_override' or reason is not null)
);

create table incident_report (
  session_id      uuid references lesson_session,
  reporter_id     uuid not null references user_account,
  subject_user_id uuid not null references user_account,
  category        incident_category not null,
  severity        incident_severity not null default 'medium',
  description     text not null,
  status          incident_status not null default 'open',
  assigned_to     uuid references user_account,
  resolved_at     timestamptz,
  resolution      text
);

create table suspension (
  user_id     uuid not null references user_account,
  incident_id uuid references incident_report,
  reason      text not null,
  starts_at   timestamptz not null,
  lifted_at   timestamptz,
  lifted_by   uuid references user_account
);
```

`booking.commission_bps` is copied from configuration when the booking is created, so later fee changes never alter past bookings. The exclusion constraint on `lesson_session` is the final guard against double booking, whatever the application code does.

## 6. Payments and ledger

Ten tables record every cedi that moves, with a double-entry ledger as the single source of truth. Owner: Payments and Ledger module.

```sql
create type payment_channel as enum ('mobile_money','card','bank_transfer');
create type payment_status  as enum ('initialised','pending','succeeded','failed','abandoned','refunded',
                                     'partially_refunded');
create type account_type    as enum ('asset','liability','revenue','expense');
create type entry_direction as enum ('debit','credit');
create type refund_status   as enum ('requested','approved','processing','succeeded','failed','rejected');
create type payout_method   as enum ('mobile_money','bank');
create type payout_status   as enum ('eligible','queued','processing','succeeded','failed','frozen','reversed');

create table payment (
  reference          text not null unique,        -- sent to Paystack
  booking_id         uuid not null references booking,
  payer_id           uuid not null references user_account,
  amount_pesewas     bigint not null check (amount_pesewas > 0),
  currency           char(3) not null default 'GHS',
  channel            payment_channel,
  status             payment_status not null default 'initialised',
  provider           text not null default 'paystack',
  provider_reference text unique,
  provider_fee_pesewas bigint,
  paid_at            timestamptz
);

create table webhook_event (
  provider     text not null,
  event_id     text not null,
  event_type   text not null,
  payload      jsonb not null,
  received_at  timestamptz not null,
  processed_at timestamptz,
  unique (provider, event_id)                    -- replay protection
);

create table ledger_account (
  code          text not null unique,            -- e.g. 'platform:commission', 'tutor:<id>:payable'
  type          account_type not null,
  owner_user_id uuid references user_account
);

create table ledger_transaction (
  kind            text not null,                 -- 'payment_received','session_earned','payout_sent',...
  idempotency_key text not null unique,
  booking_id      uuid references booking,
  description     text,
  posted_at       timestamptz not null
);

create table ledger_entry (
  transaction_id uuid not null references ledger_transaction,
  account_id     uuid not null references ledger_account,
  direction      entry_direction not null,
  amount_pesewas bigint not null check (amount_pesewas > 0)
);

create table refund (
  payment_id         uuid not null references payment,
  amount_pesewas     bigint not null check (amount_pesewas > 0),
  reason_code        text not null,
  status             refund_status not null default 'requested',
  provider_reference text unique,
  requested_by       uuid not null references user_account,
  approved_by        uuid references user_account
);

create table payout_account (
  tutor_id           uuid not null references tutor_profile,
  method             payout_method not null,
  provider_code      text not null,              -- network or bank code
  account_number_enc bytea not null,
  account_last4      text not null,
  account_name       text not null,
  recipient_code     text,                       -- Paystack transfer recipient
  verified_at        timestamptz,
  approved_by        uuid references user_account,
  second_approver_id uuid references user_account,
  is_active          boolean not null default false
);

create table payout (
  tutor_id           uuid not null references tutor_profile,
  payout_account_id  uuid not null references payout_account,
  amount_pesewas     bigint not null check (amount_pesewas > 0),
  status             payout_status not null default 'eligible',
  idempotency_key    text not null unique,
  provider_reference text unique,
  eligible_at        timestamptz not null,
  sent_at            timestamptz,
  failure_reason     text
);

create table payout_item (
  payout_id  uuid not null references payout,
  session_id uuid not null unique references lesson_session   -- a session is paid once
);

create table reconciliation_run (
  run_date   date not null unique,
  status     text not null,
  mismatches integer not null default 0,
  report     jsonb
);
```

**Ledger rules**

- `ledger_entry` and `ledger_transaction` allow insert only. Update and delete are revoked from the application role.
- A deferred constraint trigger checks that debits equal credits in every transaction before commit.
- Balances are computed from entries. No table stores a mutable balance.
- Only one `payout_account` per tutor may be active, enforced by a partial unique index.
- The ledger design is unchanged whichever settlement option Paystack confirms. Only the account codes and posting times differ.

## 9. Integrity, indexes and access rules

The database itself enforces the rules that must never break, so a bug in application code cannot corrupt money, bookings or privacy.

**Rules enforced in the database**

| Rule | Mechanism |
| --- | --- |
| A tutor cannot be double booked | Exclusion constraint on `lesson_session` |
| A session is reviewed once and paid out once | Unique keys on `review.session_id` and `payout_item.session_id` |
| A webhook or job is processed once | Unique keys on `webhook_event` and on every `idempotency_key` |
| Debits equal credits | Deferred constraint trigger on `ledger_entry` |
| Ledger and audit history cannot be rewritten | Update and delete revoked from the application role |
| One active payout account per tutor | Partial unique index where `is_active` |
| No chat without a request or booking | Check constraint on `conversation` |
| Home bookings carry an address | Check constraint on `booking` |
| A second approver differs from the first | Check constraint on `credential_review`; same rule on `payout_account` |

**Key indexes beyond foreign keys**

| Table | Index | Serves |
| --- | --- | --- |
| `tutor_profile` | GiST on `base_location` | Distance search for home lessons |
| `tutor_profile` | GIN on `search_vector` | Text search |
| `tutor_profile` | Partial B-tree on `(reputation_score desc)` where `listing_status = 'listed'` | Ranking listed tutors |
| `tutor_subject` | `(subject_id, class_level_id, tutor_id)` | Subject and level filter |

**Database roles**

| Role | Rights |
| --- | --- |
| `tl_migrator` | Owns the schema; used only by the migration job |
| `tl_app` | Read and write on application tables; insert only on ledger and audit tables |
| `tl_readonly` | Read on non-sensitive views for analytics; no access to encrypted columns, messages or child tables |

**Sensitive columns**

| Column | Protection |
| --- | --- |
| `guardian_address.address_enc`, `ghanapost_gps_enc` | Field encryption; decrypted only by the Booking service |

Row-level security in PostgreSQL is not used in Phase 1. Tenant and ownership checks live in each module's repository layer and are covered by API tests. Row-level security on `organisation_id` is planned for Phase 3, when institutions join.

## 10. Migrations, seed data and retention

Prisma Migrate owns ordinary tables. Raw SQL migrations add what Prisma cannot express: PostGIS columns, the exclusion constraint, the ledger trigger, partial indexes and role grants.

**Migration rules**

1. Migrations run as a separate job under `tl_migrator`, before new application code starts.
2. Every change is backward compatible with the running version. Breaking changes use expand, backfill, then contract, across at least two releases.
3. No migration edits ledger or audit rows. Corrections are new ledger entries.
4. Each migration is reviewed in a pull request and run first on staging.
5. Large backfills run as background jobs in batches, not inside the migration.

**Initial migration order**

| Step | Contents |
| --- | --- |
| 0001 | Extensions and enum types |
| 0002 | Reference tables: region, district, locality, subject, class level, curriculum |
| 0003 | Platform tables: organisation, config, feature flags, audit log, outbox |
| 0004 | Identity and family tables |
| 0005 | Tutor and verification tables |
| 0006 | Marketplace and session tables, including the exclusion constraint |

**Retention.** These periods are proposals for counsel to confirm in Phase 0. A scheduled job purges or de-identifies rows when they expire.

| Data | Proposed retention | Action at expiry |
| --- | --- | --- |

Fourteen tables added for Marketplace Lite and the in-app classroom, both in Phase 1. Owners: Marketplace and Online Classroom modules. They run as migrations 0010 and 0011.

```sql

                                     'exam_prep','worksheet','teaching_material');

  contents          text,
  price_pesewas     bigint not null check (price_pesewas >= 0),
  page_count        integer,
  cover_key         text,

  search_vector     tsvector,

  add constraint payment_has_one_target
```

**Rules**

- A file is downloadable only through a live `library_entitlement`; every download writes a `download_event` with its own stamped copy.
- `product_file.sha256` flags exact duplicates of files already sold by another seller before review.
- `order_item` copies price and commission at purchase, like bookings do.
- Online attendance is derived from `room_event` rows; the tutor must be present for at least 80% of the booked time.
- Recordings are deleted by a scheduled job at `expires_at`, and only exist when a guardian's consent record is attached.

**Indexes:** GIN on `product.search_vector`; `product (subject_id, class_level_id, term)` partial where `status = 'live'`; `product (sold_count desc)` partial where live, for best sellers; `room_event (room_id, occurred_at)`; `lesson_recording (expires_at)`.
